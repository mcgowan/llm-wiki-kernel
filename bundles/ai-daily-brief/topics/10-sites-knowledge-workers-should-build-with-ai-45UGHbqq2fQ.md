# Overview

In this weekend "big think" episode, Nathaniel Whittemore takes OpenAI's Tuesday launch of Codex Sites — a feature that lets users publish what they build with Codex directly as a website or web app, without wiring together hosting like Vercel and a database like Supabase or using an all-in-one vibe-coding tool like Replit or Lovable — as the jumping-off point for a broader thesis: the website or simple web app is becoming a new unit of work output, a new "anchor artifact" in the knowledge worker's toolkit. For decades, he argues, knowledge workers packaged thinking into docs, decks, spreadsheets, and PDFs not because those formats were the best carriers of knowledge, but because building anything with code was limited to a specific few; AI has changed that cost structure so completely that any semi-capable person can now generate a useful, good-looking website as easily as they used to throw together a deck.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]

Whittemore first catalogs roughly a dozen problems with traditional downloadable artifacts that websites solve — versioning, distribution friction, forced linear navigation, scattered context, passivity, audience fit, actionability, reusability, observability, presentation, permissioning, and agent readability — then runs through 18 concrete examples of documents knowledge workers should consider rebuilding as sites, from slide decks becoming narrative websites to media kits becoming press sites.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]

# Key points

- OpenAI announced Codex Sites as part of a batch of Codex updates that week; it natively publishes Codex builds as shareable websites or web apps, collapsing what previously required Vercel + Supabase + Claude Code/Codex or an all-in-one tool like Replit or Lovable.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Downloadable files are snapshots that go out of date the moment they are sent ("plan_final_final, plan_final_v8"); a URL gives knowledge a canonical home that is always the current version — a more generalist fix than intermediate tools like DocSend or Google Docs.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Docs are linear, spreadsheets tabular, PDFs paged — each forces one structure on every reader; a site can organize the same material by topic, role, urgency, or depth so different audiences navigate their own way.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Sites produce observability signal — what got read, clicked, searched, shared, revisited, abandoned — whereas sending a deck is "dropping something into the void and hoping it works."[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Cloudflare reported that week that agent and bot browsing exceeded human browsing for the first time ever; Whittemore argues websites can be designed for agent consumption, while PDFs, docs, CSVs, and PowerPoints look brittle in an agent-mediated paradigm.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- The 18 examples include: slide deck → narrative website (his top recommendation, with tools like Gamma already collapsing the deck/website distinction); strategy memo → strategy site; research report → research hub; spreadsheet → data site with dashboards and filters; sales proposal → proposal microsite with interactive ROI/pricing toggles; client update → client portal; project brief → project home page; case study PDF → interactive case page with embedded rich media.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Some examples change the artifact's nature entirely: a competitive analysis becomes a living competitive-intelligence hub, potentially with an OpenClaw-style agent continuously researching and updating it.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Further examples: static training materials → dynamic learning sites (as with his own Agent OS, Claw Camp, and AIDB New Year programs, each with purpose-built platforms despite being free); employee handbooks → living handbook sites; board materials → board portals separating required reading from backup; investor updates → investor pages with potentially real-time metrics; job descriptions → candidate sites; brand guidelines → brand system sites; media kits → press sites.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
- Patterns to watch for in deciding what to convert: artifacts that get forwarded around a committee without you in the room, things that keep evolving after you "finish" them, and things that scatter across channels.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]

# Takeaways

Whittemore's core observation is that a huge part of the vibe-coding explosion is simply knowledge workers discovering that websites are better ways to share information than the traditional artifacts they used to use — and that platforms like Coda embedding site features means the trend will only expand. Files are constrained containers whose problems (versioning, access, portability) were pronounced enough to spawn entire companies solving them for single formats; websites offer interaction, access control, and versioning natively in a more shareable form. His strongest single recommendation: start exploring whether, on average and by default, the slide decks you currently build should just become narrative websites instead.[^10-sites-knowledge-workers-should-build-with-ai-45UGHbqq2fQ]
